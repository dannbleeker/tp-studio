# Internationalisation — the catalogue contract

TP Studio ships **English only**. This note describes the seams that exist so a
second locale is additive and compile-checked rather than a refactor, and the
constraints that shaped them.

## Why it looks like this

Three properties of this codebase drove the design; changing any of them would
change the answer.

1. **There is no React context anywhere in `src/`.** `createContext` /
   `useContext` appear zero times, there is no shared test render helper, and
   119 test files call RTL `render()` directly. An `I18nProvider` would be the
   first context here and would need a wrapper added to every one of those
   files. So **locale lives in the Zustand preferences slice** like every other
   preference, and `resetStoreForTest` resets it for free.

2. **`validate(doc)` is memoized twice** — a `WeakMap<TPDocument, Warning[]>`
   plus a 32-entry fingerprint LRU (`src/domain/validators/index.ts`). Passing a
   catalogue into it would mean keying both caches on the locale as well as the
   document. So **`validate()` stays locale-free** and emits a serializable
   `(messageKey, params)` pair that the inspector resolves.

3. **knip runs at `error` level** for `files`, `exports`, `types`,
   `duplicates`, and `enumMembers`. That rules out an unconsumed barrel, an
   unreferenced file, and any TS `enum`.

## The pieces

| File | Role |
| --- | --- |
| `src/i18n/locales/en.ts` | The English catalogue. **Source of truth for the shape.** |
| `src/i18n/types.ts` | `Messages = typeof en`, `Locale`, `ClrParams`, `ClrMessageKey`. |
| `src/i18n/locale.ts` | `LOCALES` / `SELECTABLE_LOCALES` / `LOCALE_LABEL` / `BCP47_BY_LOCALE` / `isLocale`. |
| `src/i18n/registry.ts` | Lazy loaders + the external store `useT` subscribes to. |
| `src/i18n/useT.ts` | `useT()` → the active `Messages`. |
| `src/i18n/clr.ts` | `resolveClrMessage` / `resolveClrActionLabel`. **React-free.** |
| `src/i18n/useClrText.ts` | React-side CLR resolvers. |
| `src/i18n/pseudo.ts` | The QA pseudo-locale, derived from `en`. |

### `useT()` returns the catalogue, not a lookup function

```tsx
const t = useT();
<Field label={t.settings.appearance.theme} />
```

Not `t('settings.appearance.theme')`. Every access is checked by `tsc` against
`Messages`, so a typo is a compile error rather than a missing-key placeholder,
and there is no runtime key parsing.

### `en.ts` is deliberately NOT `as const`

`as const` would narrow every value to its own string literal type, so
`Messages` would demand that a Danish catalogue contain the literal
`'Undesirable Effect'`. Widened `string` values keep the **shape** enforced —
keys present, interpolation signatures matching — while leaving the copy free.

### Static copy is a string; interpolated copy is a function

```ts
'clarity.question': 'Statements should be declarative, not questions.',
'clarity.too-long': (p: ClrParams) => `Title is over ${num(p.limit)} words — …`,
```

Making the arrow part of the type means a locale cannot quietly drop a
parameter, and it keeps ICU placeholder parsing (and a dependency) out of the
app. Each catalogue bakes in its own BCP-47 tag when calling `plural()` /
`formatList()` — the English catalogue already knows it is English.

### CLR warnings carry a key, not copy

`makeWarning(doc, ruleId, target, messageKey, params?, variant?)` renders
`Warning.message` in English from the catalogue **and** stores
`messageKey` + `params`. Renderers use `useClrText().message(w)`, which prefers
the key and falls back to the English string.

`message` is retained on purpose. It keeps every existing message assertion
working, and because it renders through the same catalogue entry the UI uses, a
mis-named interpolation parameter produces a visibly broken English string that
the validator suite catches immediately.

`clr.ts` must stay React-free: it is imported by
`domain/validators/shared.ts`, and pulling `useT` (and therefore `@/store`)
through that path would create a domain → store import cycle. That is what
`useClrText.ts` exists to avoid.

## Adding a locale

1. Add the id to `Locale` in `src/i18n/types.ts`, then to `LOCALES`,
   `SELECTABLE_LOCALES`, `LOCALE_LABEL` (an **autonym** — a language names
   itself in its own language), and `BCP47_BY_LOCALE` in `src/i18n/locale.ts`.
   Adding the second entry to `SELECTABLE_LOCALES` is also what makes the
   Settings **Language** row appear — it is hidden while there is only one
   shipping locale, so users are never offered a choice of one.
2. Create `src/i18n/locales/<id>.ts` exporting `const <id>: Messages = { … }`.
   The `Messages` annotation is what makes `tsc` reject a missing key, an extra
   key, or a changed interpolation signature.
3. Register a **dynamic** loader in `src/i18n/registry.ts`:
   `<id>: () => import('./locales/<id>').then((m) => m.<id>)`.
   Do not import it statically — `en` is the only static import, because it has
   to be resolvable synchronously at first paint.
4. Do **not** add `src/i18n/` to `manualChunks` in `vite.config.ts`.
   `vite.config.ts:313-332` records the Session 135 incident where pinning the
   icon catalogue to its own chunk forced all of it onto the eager path.

## The pseudo-locale

`pseudo` is a QA harness, not a language. It derives every string from `en` and
wraps it in `⟦…⟧`, so any text a converted surface renders **without** brackets
is a hardcoded literal that never went through `useT`. That turns "did we miss
a string?" into an assertion — see `tests/i18n/pseudoLocale.test.tsx`.

It is in the `Locale` union (so it can be selected and rendered like any other
locale) but excluded from `SELECTABLE_LOCALES`. It is reached only through the
registry's dynamic import, so it lands in its own ~200 B chunk that production
never loads.

**It does NOT test layout.** The wrapper only brackets each string; it does not
expand length. So it catches a MISSING translation but not a German or Finnish
string overflowing a fixed-width control — the other half of what a pseudo-
locale usually buys. Adding expansion (pad to ~130% and substitute accented
glyphs) is a small change to `pseudoValue` and is worth doing before a real
locale ships.

## What is deliberately NOT done yet

- **The pattern library and examples** (~13,900 words across 104 files).
  English titles are positional arguments to `buildEntity(...)` calls, so they
  are not extractable in place; and translating a TOC tree is re-authoring
  diagrams, not swapping strings — a bad translation makes the CLR validators
  fire on the library's own content. These need per-locale document files, not
  a catalogue.
- **`docs/guide/**`** — a separate translation project with its own PDF/EPUB
  pipeline.
- **`navigator.language` auto-detect**, a `?lang=` URL override, and a
  localised PWA manifest.
- **Reading `TPDocument.locale`.** The field is persisted and validated but
  nothing consumes it (see its doc comment).
- **The remaining UI strings.** ~635 are converted. Twelve surfaces are asserted
  by `tests/i18n/pseudoLocale.test.tsx`, eleven of them with an EMPTY allow-list:
  the four Settings tabs, the Document Inspector, Help, About, the diagram-type
  picker, TitleBadge, MethodStepper and the Analysis-journey dialog. The twelfth
  — the Building-Blocks rail — allows exactly the `ENTITY_TYPE_META` labels and
  meanings, derived from that module rather than transcribed, so a string
  hardcoded in the component still fails. The Templates dialog is deliberately
  NOT asserted: its chrome is converted, but it also renders the 222 parked
  pattern strings, and an allow-list that large would rot faster than it guards.
  Alongside them: the full CLR pipeline, the 63-step method
  checklist, the 38 keyboard shortcuts, the 7-CLR scrutiny stepper, Barnard's
  five journey questions, the shared doc-links and reader-mode coaching.

  What is left is concentrated in the WORKING surface, not the chrome —
  `src/components/canvas` (4 of 32 files converted) and
  `src/components/inspector` (2 of 30), plus `command-palette`, `search`,
  `comments`, `import`, `export`, `print` and `quick-capture` at zero. See
  `NEXT_STEPS.md` for the running counts and for the three items that need a
  design decision rather than extraction (the lazy catalogue segment for
  pattern metadata, the toast key seam, and per-locale sentence templates).

  A raw `grep` over `src/` returns ~2,684 capitalised literals, but that count
  double-lists duplicates and includes 1,182 pattern/example diagram-content
  strings — it is not the size of this job.
